# iOS day one — MacBook runbook

Everything here is prepared so that day one on the Mac is **execution, not
discovery**. Work top to bottom. Where a step needs a decision rather than a
command, it says so.

Companion docs: `CAPACITOR.md` (what is already wired and why), `OPERATIONS.md`
(accounts and billing).

---

## 0. Before you touch the Mac — one decision that gates the listing

**Age rating.** Players stake tokens and the winner takes the pot. Rating boards
generally treat that as *simulated gambling*, which lands at 17+ (Apple) and
restricts distribution in some regions on Google Play. Your Terms currently say
**13+**, with an open `TODO(owner)` on that exact line in
`frontend/src/components/legal/TermsOfService.js`.

Those two cannot both stand. Decide before filling in the rating questionnaire,
because the answer changes the questionnaire, the store copy, and possibly
whether the buy-in framing stays as it is.

What you *can* say with confidence, and it is worth saying plainly in any
review correspondence:

- There is **no payment path in either direction**. No payment SDK exists in the
  repo; `transactions.transaction_type` has no deposit or withdrawal value.
- Tokens are minted only by free grants and are otherwise strictly conserved —
  `assertExactPot` in `backend/src/settlement/gameSettlement.js` makes a
  non-conserving settlement a hard error.
- The Terms already state tokens cannot be bought, sold, or redeemed.

## 2. Scaffold the Xcode project

The web side is already configured — `frontend/capacitor.config.json` has
`appId: com.playsluff.app`, `appName: Sluff`, `webDir: build`.

```bash
cd frontend
npm ci
npm run build            # produces frontend/build, the webDir
npx cap add ios          # scaffolds ios/, runs CocoaPods
npx cap sync             # copies web assets + native deps
npx cap open ios         # opens Xcode
```

After **any** web change: `npm run build && npx cap sync`.

## 3. Info.plist — the entries that do not exist yet

`ios/App/App/Info.plist` is generated by step 2, so these cannot be committed in
advance. Add them immediately after scaffolding.

| Key | Value |
|---|---|
| `NSMicrophoneUsageDescription` | `Sluff uses your microphone only for live voice chat with the other players at your table, and only after you turn voice chat on. Audio is sent directly between players and is never recorded or stored.` |
| `ITSAppUsesNonExemptEncryption` | `NO` |

**The microphone string is not optional.** A missing or vague purpose string is
a rejection on its own, and the app does request the microphone —
`frontend/src/utils/VoiceChat.js` calls `getUserMedia`.

The claim in that string is true and worth keeping true: voice is peer-to-peer
WebRTC, the server relays only SDP/ICE, there is no `MediaRecorder` anywhere,
and as of the opt-in change the microphone is not touched at all until the
player turns voice on. If voice chat ever starts recording, this string must
change first.

`ITSAppUsesNonExemptEncryption: NO` is the standard answer for an app whose only
cryptography is HTTPS and WebRTC's built-in transport security. It saves an
export-compliance prompt on every single upload.

No other permissions are needed: no camera, no photos, no location, no contacts,
no push, no tracking. Do not add capabilities you do not use — each one invites
a question.

## 4. Signing and first run

In Xcode: select the **App** target → Signing & Capabilities → check *Automatically
manage signing* → pick your Team. Bundle identifier must read
`com.playsluff.app`.

Run on a simulator first, then on a physical device. **The device run is the one
that matters** — the simulator will not show you the safe-area behaviour around
the home indicator, which is the known open item for the bottom card hand.

### What to check on a real phone, in order

1. **Boot**: the ident plays, the lobby loads, the footer clears the home indicator.
2. **Safe areas**: the card hand sits above the home indicator; the header clears
   the notch/Dynamic Island. `CAPACITOR.md` lists this as the outstanding tuning item.
3. **A full game**: deal → bid → play a trick → round recap. Use a Quick Play
   table so bots fill the seats.
4. **Card physics under a thumb** — the flick gesture is the crown jewel and has
   only ever been tested with a mouse and in the harness.
5. **The 5-second turn nudge**: sit still on your turn and confirm the rim light,
   the "YOUR MOVE" tab and the card wave read correctly at phone size, and that
   the haptic fires (Capacitor Haptics, not the web Vibration API, on iOS).
6. **Voice chat opt-in**: confirm the microphone prompt appears **only** after
   tapping "Turn on voice", and that the purpose string reads correctly in it.
7. **Account deletion**: Lobby menu → Account → Account Settings. Use a throwaway
   account; this is the one flow never exercised end to end.
8. **Backgrounding**: background mid-game and return; the socket should reconnect
   and the table should still be there.

## 5. TestFlight

```bash
cd frontend && npm run build && npx cap sync
```

In Xcode: set the build number, Product → Archive → Distribute App → App Store
Connect → Upload.

In App Store Connect, the app record needs: name, subtitle, description,
keywords, support URL, marketing URL, **privacy policy URL**, age rating
questionnaire, and the App Privacy nutrition label.

### Privacy nutrition label — the answers

This is genuinely simple, which is the payoff for having no ad SDK, no
analytics, and no third-party login.

| Question | Answer |
|---|---|
| Data used to track you | **None** |
| Third-party advertising | **None** — the in-app ad components are retired and unmounted |
| Analytics SDK | **None** — first-party funnel counters only, cookieless, 4 event names |
| Contact info | Email address, linked to identity, for account management |
| User content | Chat messages and support/feedback text, linked to identity |
| Identifiers | Username only. No IDFA, no device identifier |
| Diagnostics | Crash data: **first-party**, anonymous, not linked to identity. No SDK — reports go to our own `/api/errors` (message, stack, URL, build id only; never an account id). Declare "Crash Data — not linked to you". |

Nothing is collected for tracking, so **App Tracking Transparency does not
apply** and no `NSUserTrackingUsageDescription` is needed. The crash reports
are the one Diagnostics declaration, and they are deliberately anonymous so it
stays "not linked to you".

### Privacy policy URL

`https://playsluff.com/privacy`

**Verify this in a private window before pasting it in.** The page is a real,
substantive document, but it renders only for logged-out visitors — signed in,
that path falls through to the lobby. A reviewer will hit it logged out, so it
should be fine, but it costs ten seconds to confirm and a wrong URL is a
rejection.

## 7. Optional: build iOS in CI

`.github/workflows/ci.yml` already runs both test suites and the web build on
`ubuntu-latest` with pinned action SHAs. A macOS job can archive and upload to
TestFlight without the Mac being switched on, which matters if the Mac ever
becomes the bottleneck.

It needs four repository secrets — an App Store Connect API key (issuer id, key
id, .p8 contents) and a distribution certificate — so set it up *after* a manual
upload has succeeded and you know the signing works. Doing it before means
debugging signing and CI simultaneously.

## 8. Android, for comparison

Android is buildable on Windows and needs no Mac. `@capacitor/android` is not
installed yet and there is no `android/` directory. A Google Play Console
account is **$25 one-time** versus $99/year. If iOS stalls on hardware or
enrolment, Android is the faster route to a real device in a real store.
